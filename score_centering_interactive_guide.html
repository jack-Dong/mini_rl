📄 Score Centering Stabilizes Off-policy Reinforcement Learning

一句话先看懂：Score Centering 到底在修什么 Bug？

arXiv 原论文 ↗ GitHub 源码 ↗

训练大模型做强化学习（比如 GRPO、PPO）时，为了追求速度，我们让高速推理引擎（Sampler，qθ）去“做题写答案”，再把答案交给高精度训练引擎（Trainer，pθ）去“打分改参数”。但因为量化（FP8/INT4）、算子误差或网络延迟，两个引擎对同一个词的概率判断总有一点点偏差（Training-Inference Mismatch, TIM）。 这篇论文发现：哪怕这一点点偏差很小，也会像一只看不见的手一样，在每一步训练里产生一个固定方向的推力，把模型参数活活推崩——作者把这个现象命名为 Drift（梯度漂移）。而 Score Centering 只需要用一道简单的减法，就能把这股歪风邪气完美抵消掉。

❌ 痛点：漂移 (Drift) 而不是单纯噪声

以前大家以为 TIM 只是让梯度抖动变大，其实它制造的是方向一致的系统性偏置，每步都在累加，最终让词分布坍塌。

⚠️ 老办法：重要性采样 (IS / TIS) 两难

乘以权重 p/q 在深度量化下会让方差爆炸；一截断（如 TIS 限制上限 2.0）又破坏了无偏性，残余漂移卷土重来。

✅ 新办法：Score Centering (零超参可叠加)

直接在梯度里减去推理引擎下的期望 Score，像消除天平零点误差一样把 Drift 清零，且能和 TIS/MIS 自由组合。

模块 01 · 前因后果与直觉动画

为什么“左右手概率差一点”，模型就会练崩？

1 大模型 RL 的两套系统

推理（生成几千字思维链）极耗显存带宽，训练（算反向传播）极耗算力。所以业界标配拆成两套引擎：
• Sampler (qθ)：如 vLLM / SGLang，常用 FP8/INT4 量化图快。
• Trainer (pθ)：如 FSDP / Megatron，用 BF16/FP32 精确算梯度。

2 什么是“盲目夸奖测试”？

想象一个极简思想实验：假设不管模型输出 Token A 还是 Token B，我们每次都给出完全相同的奖励 R = +1。
既然大家都得满分，没有任何一个词比另一个词更优秀，模型概率分布理论上应该保持原地不动（期望梯度 = 0）！

3 Drift 是怎么酿成大祸的？

假设 Trainer 觉得 A 和 B 概率都是 50%，但因为量化误差，Sampler 把 A 算成了 65%、B 算成了 35%。
结果收到的样本里 A 占了大头！Trainer 每收到一个样本就夸一次它，导致 A 被夸的次数远多于 B——模型就像被偏心眼骗了一样，不断把 A 推向 100%，训练直接崩塌！

模块 03 · 零跳步数学推导

每个公式的基础原理与 7 步完整推理

点击下方步骤标签，从大白话微积分一路推到论文的 Top-k 工程实现公式。

Step 1：策略梯度里为什么会出现 ∇θ log pθ(y)？

在 RL 中，我们的目标是最大化平均奖励： J(θ) = Ey ~ pθ[R(y)] = ∑y pθ(y) · R(y)。 问题是“采样抽词”这个动作本身不可导，但概率 pθ(y) 可导！利用高中微积分求导法则 (ln f)' = f' / f，即 ∇θ pθ = pθ · ∇θ log pθ：

∇θ J(θ) = ∑y R(y) · ∇θ pθ(y) = ∑y pθ(y) · R(y) · ∇θ log pθ(y) = Ey ~ pθ [ R(y) · ∇θ log pθ(y) ]

• 高亮部分 sθ(y) = ∇θ log pθ(y) 在统计学里就叫做 Score Function（得分函数）。
• 对于神经网络最后一层的 logits z（通过 Softmax 变成概率 p），求导结果极其简洁：∇z log p(y) = ey − p。
• 物理直觉：如果采样到了词 A，Score 向量就是把词 A 的 logit 向上拉升 (1 − pA)，同时按各自概率比例把其他词往下压 (−pB, −pC)——因为概率总和必须保持 100%，拉高一个就必须压低其余！

Step 2：核心基石——为什么在真实分布 pθ 下，Score 的期望恒等于 0？

这是整篇论文的数学地基，推导只有短短 4 行，请逐行看懂：

  1. ① 归一性公理：所有词的概率之和永远等于常数 1：   ∑v ∈ V pθ(v) = 1
  2. ② 两边同时对参数 θ 求导：常数 1 的导数为 0：   ∇θ (∑v ∈ V pθ(v)) = ∑v ∈ V ∇θ pθ(v) = 0
  3. ③ 替换导数形式：把 ∇θ pθ(v) = pθ(v) · ∇θ log pθ(v) 代入上式：   ∑v ∈ V pθ(v) · ∇θ log pθ(v) = 0
  4. ④ 写成期望形式：这就得到了大名鼎鼎的 零均值 Score 恒等式：   Ev ~ pθ[∇θ log pθ(v)] = 0
🎲 互动验算器：任意随机一组概率 p，加权 Score 之和永远是 0.000000

Step 3：TIM 破局——一旦换用推理引擎 qθ 采样，Drift 立刻诞生！

现在进入真实工程场景：句子不是由 pθ 采样的，而是由存在量化误差或滞后的推理引擎 qθ 采样的。再做一次“恒定奖励 R = 1 思想实验”：

Ey ~ qθ [ 1 · ∇θ log pθ(y) ] = ∑v ∈ V qθ(v) · ∇θ log pθ(v) ≠ 0

• 对 Softmax 层 logits 求导代入试试看：
∑v q(v)(ev − p) = (∑v q(v) ev) − (∑v q(v)) p = q − p！
• 这意味着：只要推理和训练概率差一点（q ≠ p），每一步训练都会产生一个纯属幻觉的推力 (q − p)。而且就算 Advantage 经过组内中心化（比如 GRPO 减去组均值，期望为 0），只要正负样本刚好撞上微小的推理偏差，这个系统性误差依然会沿着每一步积累，论文把这种非零期望梯度定义为 Drift（漂移）。

Step 4：为什么传统重要性采样（IS / TIS）搞不定重度量化？

1. 原始 IS：理论上无偏，实际上梯度爆炸

为了把采样分布 q 改回 p，传统办法乘上一个修正比率 w(y) = pθ(y) / qθ(y)：

∑y q(y) · p(y)q(y) ∇ log p(y) = ∑y p(y) ∇ log p(y) = 0

致命伤：在 FP4/INT4 重度量化下，某个低概率词可能被量化器算成 q=0.0001 而 p=0.02，比率瞬间飙到 200 倍！偶尔采到一次就直接把梯度炸飞（方差爆炸）。

2. 截断 IS (TIS/MIS)：压住了方差，放回了 Drift

工程上只好强行截断：w(y) = min(p(y)/q(y), 2.0)（TIS）或超出范围直接丢弃（MIS）。

m(v) = q(v) · w(v) = min(p(v), 2 q(v)) ≠ p(v)

致命伤：一旦发生截断，等效质量 m(v) 不再等于 p(v)！于是 ∑v m(v) ∇ log p(v) ≠ 0——Drift 立刻死灰复燃！量化越狠、截断越频繁，残余 Drift 越严重。

Step 5：Score Centering 的核心思想——与其乘法硬掰，不如直接减去偏置！

既然任何权重 w(y) 下（包括纯 REINFORCE 时的 w=1，以及 TIS 时的截断权重），每个词的等效采样质量都是 m(v) = qθ(v) · w(v)，它的期望漂移就是 s̄ = ∑v m(v) ∇θ log pθ(v)。
Score Centering 的做法极为优雅：直接在每一步的 Score 向量里把这个期望减掉（中心化归零）！

gSC(y) = R · ( w(y) ∇θ log pθ(y) − ∑v ∈ V m(v) ∇θ log pθ(v) )
① 严格零漂移证明
对 y ~ qθ 求期望（设 R=1）：
Eq[gSC] = ∑ q(y)w(y)∇log p(y) − ∑ m(v)∇log p(v) = s̄ − s̄ = 0！无论多严重的量化与截断，Drift 永远严格等于 0！
② On-policy 下自动隐身
当没有偏差（q = p, w = 1）时，m(v) = p(v)，减去的项正好等于 ∑ p(v)∇log p(v) = 0，完全变成无操作（No-op），不干扰任何正常训练。
③ 加性设计可自由叠加
纯加性修正（w = 1）就能在重度量化下打败 TIS；而面对异步滞后（Staleness）时，还可以直接套在 TIS/MIS 外面（TIS + SC），兼顾低方差与无偏性。

Step 6：自动微分技巧——如何把它写进一个标量 Loss 里？

在 PyTorch/JAX 中，我们不直接手算模型所有参数的梯度向量，而是定义一个标量 loss，然后调用 loss.backward()。利用自动微分对线性求和求导的特性，Score Centering 的单 token 损失函数直接写成：

LSC = − sg(R) · [ sg(w(yt)) · log pθ(yt) − ∑v ∈ V sg(m(v)) · log pθ(v) ]
🔍 为什么必须用 sg(...)（stop_gradient / .detach()）包住 m(v) 和 w？

1. 我们要的是 m(v) · ∇θ log pθ(v)，这里的 m(v) 只是个已知的常数权重！如果不加 .detach()，m(v) 内部如果包含了 pθ(v)（例如 TIS 里有 p/q），反向传播就会沿着 m(v) 对参数求导，凭空多出多余的梯度项把零漂移性质破坏掉。

2. 加上 .detach() 后，PyTorch 求导时把 sg(m(v)) 当成纯数字常数，求导结果一字不差地还原为 −R · (w(y)∇log p(y) − ∑ m(v)∇log p(v))！

Step 7：工程绝杀——词表有 15 万个词，怎么只算 Top-k 就等价于全词表？

推理引擎如果每个 token 都传回 150,000 个词的 logprobs，通信和显存会瞬间爆炸。论文只让推理引擎传回概率最高的 Top-k 个词（默认 k=128），然后用极巧妙的尾部重缩放（Tail Rescaling）消除剩余 149,872 个词的求和！

① 拆分词表：把全词表 V 拆成头部 H（Top-k 个词）和尾部 T（其余所有冷门词）。
② 尾部近似假设：尾部每个词概率都很小，近似认为推理尾部概率与训练尾部成等比缩放： qv ≈ ρ · pv，其中总尾部质量比 ρ = qtail / ptail = (1 − ∑H qv) / (1 − ∑H pv)。
③ 尾部等效权重变成统一常数 α：在尾部每个词上，比率都是 pv / qv = 1/ρ，所以等效质量系数 α = ρ · w(1/ρ) 是与词无关的常数（当不用 IS 时，w=1，直接就是 α = ρ）！
④ 见证奇迹的恒等变形：再次祭出 Step 2 的法宝 ∑V p(v)∇log p(v) = 0，得出 ∑T p(v)∇log p(v) = −∑H p(v)∇log p(v)！于是：
∑v∈V m(v)∇log p(v) = ∑v∈H m(v)∇log p(v) + α ∑v∈T p(v)∇log p(v) = ∑v∈H (m(v) − α · p(v)) ∇log p(v)
👉 这就是代码里 residual = q_head * head_weight - alpha * p_head 与 correction = (residual.detach() * head_logp).sum(-1) 的全部秘密！整个尾部梯度自动抵消，计算图只需要反传 Top-k 个元素！
